# 🛠️ SpiritPet 技术选型说明

> 版本：v1.0 · 2025
---
## 总览

| 层级 | 选型 | 版本 |
|------|------|------|
| 桌面框架 | **Tauri** | v2.x |
| 前端渲染 | **Vue 3** | v3.x + TypeScript |
| 后端服务 | **Go** | v1.22+ |
| 结构化存储 | **SQLite** (mattn/go-sqlite3) | - |
| AI 接口 | OpenAI 兼容 API | 用户自配 Key + Model |
| 构建产物 | 单文件安装包 (.exe / .dmg / .deb) | Sidecar 打包 |
---
## 1. 桌面框架：Tauri
---
### 为什么不是 Electron？

| 对比项 | Tauri | Electron |
|--------|-------|----------|
| 安装包体积 | ~5MB | ~150MB+ |
| 内存占用 | ~20MB | ~150MB+ |
| 透明窗口 + 点击穿透 | 原生支持 | 原生支持 |
| 系统托盘 | 原生支持 | 原生支持 |
| 后端语言 | Rust（可选 Go Sidecar） | Node.js |
| 社区成熟度 | 快速增长中 | 极其成熟 |

**结论**：对于一个需要常驻用户桌面的宠物应用，体积和内存是硬指标。Electron 一个空壳 150MB，用户可能还没看到蛋就先卸载了。Tauri ~5MB 的 footprint 更适合桌面小工具这个品类。

### Tauri Sidecar 机制

Tauri 允许将任意原生二进制作为 Sidecar（副驾进程）打包到安装包中，在应用启动时自动拉起、退出时自动销毁。这让 Go 后端和 Tauri 前端的组合成为一个双击即用的整体。

---
## 2. 后端服务：Go
---
### 核心考量

SpiritPet 的后端是一个常驻用户桌面的后台进程：
- 启动快（开机自启）
- 内存低（不能吃掉用户资源）
- 打包小（和 Tauri 合在一起不要太大）
- 开发效率尚可（MVP 阶段不能拖后腿）

### 对比分析

| 维度 | Go | Node.js | Python | Rust |
|------|-----|---------|--------|------|
| 打包方式 | 单二进制 ~10MB | node + node_modules ~100MB+ | 环境/打包器折腾 | 单二进制 ~5MB |
| 启动速度 | ~50ms | ~300ms | ~500ms+ | ~30ms |
| 常驻内存 | ~15MB | ~40MB | ~60MB+ | ~10MB |
| 开发效率 | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐ |
| HTTP server | 标准库 net/http | express/koa | fastapi/flask | axum/actix |
| SQLite 驱动 | mattn/go-sqlite3 | better-sqlite3 | sqlite3 | rusqlite |
| 学习成本 | 低（语法简单） | 低 | 低 | 高（所有权/生命周期） |

### 为什么不是 Node.js？

Node.js 在 MVP 阶段是最快的选择——前端是 Vue3，后端用 Node，共用 TypeScript 类型定义，开发体验丝滑。
但代价在交付阶段：一个 Node.js 后端作为常驻进程，打包时需要把 node + node_modules 一起塞进去，体积 ~100MB+。
对于用户桌面常驻这个场景，Go 的单二进制扔出去就能跑是本质优势。

### 为什么不是 Rust？

Rust 是技术上最优解——和 Tauri 同语言、极致轻量、安全性最高。
但是 MVP 阶段写 Rust 太慢了。一个简单的 HTTP server + SQLite + JSON 序列化 + AI API 调用，Go 半天写完，Rust 可能要两天。
对于还需要验证产品方向的阶段，开发效率比极致性能更重要。

### 为什么不是 Python？

Python 的问题是打包和部署：PyInstaller 打包常驻服务经常出诡异问题，用户机器上如果没有 Python 环境需要自带解释器。
Python 的优势（AI/ML 生态）在这个项目里用不上——我们只是调用 HTTP API，不是跑模型。

### 综合排序

MVP 阶段推荐：Go 🥇 > Node.js 🥈 > Rust 🥉 > Python ❌
生产阶段推荐：Go 🥇 > Rust 🥈 > Node.js 🥉 > Python ❌

Go 在写得快和交得小之间取了最佳平衡点。

## 3. 前端渲染：Vue 3
---
### 为什么不是 React？

两者都能完成工作，选 Vue 3 的原因是：
- SpiritPet 的前端复杂度不高（几个组件 + 状态管理），Vue 的模板语法更直观
- 包体积更小
- 没有选 React 的理由比选 Vue 的理由更充分——两个都行，选更趁手的

---
## 4. 数据存储：SQLite
---
### 为什么不是其他？

| 方案 | 适用场景 | 为什么不选 |
|------|---------|-----------|
| SQLite | 本地单用户结构化数据 | — |
| MySQL/PostgreSQL | 多用户网络服务 | 桌宠是单用户本地应用 |
| Redis | 高频读写缓存 | 桌宠没有高并发场景 |
| JSON 文件 | 简单配置 | 结构化查询不便 |

SQLite 是本地桌面应用的事实标准——单文件、零配置、够用。

---
## 5. AI 接口：OpenAI 兼容 API
---
用户自配 Key + Model，本地加密存储，每次对话时调用。

**为什么不是内置 API Key？**
- 成本：AI 接口按量付费，内置 Key 意味着项目方承担无限成本
- 隐私：用户用自己的 Key，数据不经过第三方
- 灵活：用户可以用便宜的模型（DeepSeek / 本地 ollama）省成本

---
## 6. 交付物：单文件安装包
---
### 用户视角

下载 SpiritPet_1.0.0_x64_setup.exe → 双击 → 下一步 → 下一步 → 完成 → 桌面上出现一枚蛋 → 配置 API Key → 开始聊天

### 开发视角

1. 编译 Go 后端 → backend.exe (~10MB)
2. tauri build（自动将 backend.exe 作为 sidecar 打包）
3. 输出 SpiritPet_1.0.0_x64_setup.exe (~18MB)

| 平台 | 安装包格式 | 预估大小 |
|------|-----------|---------|
| Windows | .exe (NSIS/MSI) | ~18MB |
| macOS | .dmg | ~18MB |
| Linux | .deb / .AppImage | ~18MB |

## 7. MVP 阶段的技术栈精简
---
MVP 还可以进一步精简——先不做 Go 后端：

MVP 极简版：Tauri + Vue3（前端直调 AI API）
- API Key 存 localStorage
- 亲密度/短期记忆用前端 JS 对象
- 直接从 Vue3 fetch OpenAI 兼容 API
- 无需 Go 后端、无需 SQLite
- 技术栈只有：Tauri + Vue3 + TypeScript
- 约 3~4 天可出 MVP

| 版本 | 技术栈 | 预计周期 |
|------|--------|---------|
| MVP 极简版 | Tauri + Vue3 | 3~4 天 |
| MVP 标准版 | Tauri + Vue3 + Go | 6 天 |
| v1.0 | 完整进化 + MBTI + 短期记忆 | 2~3 月 |

---
> 技术选型不是找最好的语言，而是找当前阶段最合适的工具组合。
> SpiritPet 的选择标准很简单：MVP 开发快、交付体积小、常驻资源低、用户安装零操心。
